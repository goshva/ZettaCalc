# Ответ на задание CPTO: Fresh House / ZETTA Home

**Позиция:** строим **детерминированное ядро** (каталог, геометрия, техкарты, ЦПР) и вокруг него тонкий слой ИИ для ввода и проверки данных. Первый продукт — бесплатный расчёт со SKU и платный базовый ЦПР на ограниченном наборе: кухня и санузел.

Артефакты репозитория отмечены ссылками. Что реализовано, а что только описано, разделено в [todo.md](todo.md).

## 1. Продукт

### 1.1 Что важнее всего для бизнеса

1. **Первый полезный расчёт без сотрудника** (бесплатно, со SKU, ценами и явными допущениями). Это вход в воронку и доказательство ценности.
2. **Платный базовый ЦПР**, собранный автоматически для стандартного случая. Это первый продукт, который продаётся сам, и единое ТЗ для подрядчиков.
3. **Аукцион подрядчиков по единому ТЗ.** Даёт комиссию и сравнимость предложений.

### 1.2 Что входит в v1 (волны 0 и 1)

- Ограниченный набор: кухня и санузел, 3–4 варианта на референс.
- Бриф с предзаполнением: 3–5 вопросов для старта, остальное допущения.
- Ввод размеров, выбор планировки из библиотеки, пересчёт при любом изменении.
- Предварительный расчёт со SKU, ценами из PIM и диапазоном.
- Базовый ЦПР: чертежи, ведомости, состав работ, смета.
- Личный кабинет проекта с версиями и допущениями.
- Аукцион подрядчиков и заказ товаров с подтверждением человеком.

### 1.3 Что отложить (волна 2 и позже)

- Генерация фото-рендеров и визуальный апселл.
- Text2SQL и самообслуживаемая аналитика.
- Расширение на спальни, детские, кабинеты.
- Профессиональный режим брифа «без ограничений» (после упрощённого).
- Маркетплейс независимых дизайнеров; авторский надзор.

### 1.4 Граница расчёт / ЦПР

| | Предварительный расчёт | Базовый ЦПР | ЦПР с опциями |
|---|---|---|---|
| Цена для клиента | бесплатно | платно | платно, опции отдельно |
| SKU, бренды, цены | да | да | да |
| Рабочие чертежи и ведомости | нет | да | да |
| Состав и последовательность работ | кратко | полностью | полностью |
| Допущения | показаны явно | показаны, требуют подтверждения | сняты замером |
| Требует эксперта | нет | только если `pending_review` | да |

### 1.5 Метрики (целевые значения проверяются на пилоте Zetta Home)

| Метрика | Цель v1 | Источник |
|---|---|---|
| Доля сессий с расчётом без сотрудника | не менее 40% к концу волны 1 | аналитика сессий |
| Время до первого расчёта | не более 5 мин | то же |
| Доля авто-ЦПР без правок, `pass^k` | 50–60% в v1 | evals на фикстурах |
| План/факт сметы | отклонение в заявленном диапазоне | сравнение с итогом ремонта |
| Доля нестандартных случаев | измеряется | статус `pending_review` |
| Ставок на тендер | не менее 3 | tender |

Стратегическая цель 90% авто-ЦПР остаётся целью; v1 стартует с 50–60%. Решение «движение верное» принимается, если три метрики растут одновременно: доля расчётов, доля авто-ЦПР и сходимость план/факт.

**Подробно:** [docs/product-scope.md](docs/product-scope.md), [сценарий первого расчёта](docs/architecture/first-calc-scenario.md), [прототипы А и В](docs/prototypes-comparison.md).

## 2. Архитектура

### 2.1 Слои данных

```
ODS (сырые выгрузки) → DDS (очищенные справочники и правила) → UDS (бизнес-сущности продукта) → DM (витрины для калькулятора и аналитики)
```

Новый источник каталога не попадает в DDS без согласованного S2T-маппинга — это gate. Цены хранятся с `catalog_snapshot`; ЦПР ссылается на снимок и не меняется задним числом. Геометрия хранится в мм (контур), сцена 1 unit = 1 м. Допущения (`assumptions`) — как данные, а не текст.

**Подробно:** [диаграмма данных](docs/architecture/data-architecture.md), [ER UDS](docs/architecture/uds-er.md), [S2T-маппинг](docs/architecture/s2t-mapping.md).

### 2.2 Сервисы

| Система | Ответственность | SLA (цель v1) |
|---|---|---|
| Catalog & Pricing (PIM) | SKU, габариты, цены со снимком | чтение p95 < 200 мс |
| Geometry Service | контур, проёмы, площади | валидация < 1 с |
| Rule Engine | подбор техкарт, объёмы | < 500 мс |
| Estimate | бесплатный расчёт со SKU и диапазоном | < 3 с |
| CPR Generator | сборка ЦПР, версии | < 60 с |
| Project Service | проект, бриф, допущения, версии | чтение < 300 мс |
| Order & Contractor | аукцион, заказ, передача ТЗ | write с `Idempotency-Key` |

**Подробно:** [архитектура сервисов](docs/architecture/service-architecture.md).

### 2.3 Контракты

- [OpenAPI](schemas/openapi/cpr.yaml) — 13 путей, включая `Idempotency-Key` на write-операциях.
- [JSON Schema ЦПР](schemas/json/cpr.schema.json) — валидация выходного документа.
- [Примеры](examples/) — `cpr_bathroom_minimal.json`, `cpr_kitchen_full.json`.

## 3. Автоматизация и ИИ

### 3.1 Матрица «процесс → ИИ / правила / человек»

| Процесс | ИИ | Правила (детерминированно) | Человек |
|---|---|---|---|
| Заполнение брифа из текста | да, подсказки и разбор | валидация полей | подтверждает допущения |
| Разбор фото и чертежа в контур | да, предложение с `confidence` | проверка замкнутости | подтверждает размеры |
| Подбор референса и варианта | да, семантический поиск | фильтры по бюджету | выбирает клиент |
| Подбор техкарты | нет | rule engine по условиям | эксперт ведёт библиотеку |
| Объёмы, расход, смета | нет | расчёт по PIM и техкартам | проверка на выборке |
| Цены и SKU | нет | только PIM | менеджер каталога |
| Сборка ЦПР | нет | CPR Generator | эксперт утверждает |
| Права доступа | нет | code-based ACL | админ |
| Заказ, оплата, передача ТЗ | нет | write с `Idempotency-Key` | подтверждение человеком |

**Правило:** ИИ готовит вход и находит ошибки, а числа и обязательные операции считает код.

**Подробно:** [матрица ИИ](docs/architecture/ai-automation-matrix.md).

### 3.2 Harness и guardrails

| Механизм | Что делает |
|---|---|
| Бюджет шагов / токенов / рублей | Ограничивает стоимость и длину сессии |
| Anti-loop (3 одинаковых вызова) | Прерывает зацикливание агента |
| Write только с `allow_write` и `approved` | Запись только с подтверждением человеком |
| LLM только через `LLMProvider` | Нет обходных путей к модели |
| Tool layer по JSON Schema | Строгий контракт на инструменты |
| Evals: code-based, `pass^k` | Проверка надёжности на фикстурах |

**Подробно:** [harness и guardrails](docs/architecture/harness-guardrails.md), код в `src/harness/`.

### 3.3 Агенты для производства (завод ZETTA)

Кроме клиентского пути, агенты на базе ИИ и детерминированного ядра повышают эффективность производства мебели и сборки:

| Процесс | Роль агента | Пример |
|---|---|---|
| **Раскрой и оптимизация** | Подбор оптимальных резов из листа с учётом остатков | Агрегирует заказы кухонь, строит карту раскроя |
| **Контроль качества** | Анализ фото/видео с линии сборки | Сравнивает фактические размеры с допуском техкарты |
| **Планирование загрузки** | Составление графика производства по срокам доставки | Учитывает доступные бригады, наличие деталей, приоритет заказов |
| **Управление остатками** | Прогноз потребности в материалах на складе | Синхронизируется с PIM и S2T, формирует заявки поставщикам |
| **Подбор комплектующих** | Проверка совместимости деталей при замене SKU | Если клиент меняет фасад, агент проверяет, подходят ли петли и ручки |

**Как подключается:** агенты используют тот же PIM, геометрию и техкарты, что и клиентский калькулятор. Результат агента — структурный JSON по JSON Schema, который проходит `pass^k` на детерминированной проверке.

### 3.4 Агенты для маркетинга

| Процесс | Роль агента | Пример |
|---|---|---|
| **Сегментация клиентов** | Кластеризация по брифу, истории просмотров, допущениям | Выявляет сегмент «молодые семьи, бюджет до 300 тыс. ₽ на кухню» |
| **Персонализация референсов** | Подбор и ранжирование идей по профилю клиента | Показывает «эконом» первым, но с возможностью апселла |
| **Генерация контента** | Описания товаров, SEO-тексты, email-рассылки | Только на основе PIM: реальные SKU, цены, габариты |
| **A/B-тестирование** | Анализ конверсий разных вариантов UI и контента | Автоматически определяет победителя, предлагает масштабирование |
| **Прогноз спроса** | Предсказание популярных стилей и материалов | На основе трендов, сезонов, истории заказов |

**Важно:** агенты маркетинга не влияют на расчёт и цены. Они работают на входных данных (контент, сегментация, аналитика) и проходят через те же guardrails.

### 3.5 Мониторинг ИТ-инфраструктуры предприятия

Платформа Fresh House требует наблюдаемости на всех уровнях. Предлагаю встроенную систему мониторинга, интегрированную с детерминированным ядром:

| Уровень | Что мониторим | Инструменты |
|---|---|---|
| **Сервисы** | Uptime, latency p95/p99, error rate | Prometheus + Grafana, health-эндпоинты FastAPI |
| **Базы данных** | Медленные запросы, размер таблиц, репликация | pg_stat_statements, pgwatch2 |
| **Очереди и поток данных** | Задержка ODS→DDS, пропускная способность S2T | Apache Kafka metrics, dead-letter queue |
| **LLM-агенты** | Стоимость сессии, token usage, anti-loop, budget | Harness Trace, dashboards cost per agent |
| **Бизнес-метрики** | Доля расчётов, pass^k, конверсия бриф→ЦПР | DM-витрины, алерты на триггеры из risks.md |
| **Серверы и контейнеры** | CPU, memory, disk I/O, network | node_exporter, cAdvisor |

**Интеграция с ядром:** каждый вызов детерминированного ядра (rule engine, estimate, cpr build) логирует trace с `cpr_id`, `version`, `duration_ms`, `assumptions_count`. Это позволяет строить дашборды надёжности и находить узкие места в подборе техкарт.

**Алертинг:** триггеры из [реестра рисков](docs/risks.md) реализуются как алерты. Например, триггер риска №1 — отклонение план/факт сметы > 20% — запускает алерт CPTO. Триггер риска №6 — менее 10 техкарт к неделе 6 — проверяется ежедневно скриптом `check_techcards.ps1`.

## 5. Риски

### 5.2 Экспертное мнение: что пересмотреть

1. **Разделить «расчёт» и «ЦПР» жёстче.** Бесплатный расчёт отвечает «сколько и из чего». ЦПР — «как построить». Нужны отдельные цена, SLA и состав.
2. **Технологии как продукт.** Версии, владельцы, тесты. Скорость роста техкарт задаёт потолок автоматизации. Бюджет на технологов важнее бюджета на интерфейс.
3. **Геометрия как актив.** Контур, проёмы и планировки дороже любой картинки. Инвестировать в ввод размеров раньше, чем в рендеры.
4. **Аукцион плюс структурированное ТЗ.** Ценность аукциона — в сравнимости. ЦПР должен выходить в формате, который подрядчик может ввести в свой расчёт без переписывания.
5. **Метрики надёжности вместо метрик активности.** Мерить `pass^k` и план/факт, а не только количество расчётов.

### 5.3 Контраргумент к стратегии

**Модель Zetta Home продаёт через консультацию, а Fresh House предполагает самообслуживание.** Менеджер зарабатывает на сопровождении клиента. Если сайт отдаёт расчёт без него, возникает сопротивление.

**Решение: гибрид.**
- Стандартный случай — через самообслуживание до ЦПР и аукциона.
- Нестандартный случай и любые сомнения — передача менеджеру одним кликом с полным контекстом (без повторного заполнения).
- Менеджер видит тот же кабинет и те же допущения, что и клиент.
- KPI менеджеров включает проекты, начатые онлайн.

**Нестандартный путь:** начинать не с кухни целиком, а с **«проверка чужой сметы»**: клиент загружает смету подрядчика, система сверяет объёмы и обязательные операции с техкартой и показывает расхождения. Низкий порог входа, быстро проверяет качество правил и даёт данные о ценах рынка.

**Подробно:** [экспертное мнение](docs/expert-opinion.md).

## 8. Подтверждение стратегии

Стратегия в документе «Задание для CPTO» — зрелая и реалистичная. Она правильно расставляет приоритеты:

1. **Детерминированное ядро** — единственный способ обеспечить проверяемость смет и ЦПР. LLM для ввода и проверки, код для расчёта.
2. **S2T как gate** — предотвращает попадание некачественных данных в DDS.
3. **pass^k вместо pass@k** — метрика надёжности, а не «иногда получается».
4. **Ограниченный старт** (кухня и санузел) — снижает риск переусложнения.
5. **Гибрид консультации и самообслуживания** — снимает конфликт между Zetta Home и Fresh House.
6. **Агенты производства и маркетинга** — естественное расширение ядра на внутренние процессы, не конкурирующее с клиентским путём.
7. **Мониторинг ИТ-инфраструктуры** — необходимая основа для надёжности пилота и масштабируемости платформы.

**Единственное предложение:** жёстче разделить расчёт и ЦПР на уровне цены и SLA, чтобы клиент понимал, что именно покупает.
